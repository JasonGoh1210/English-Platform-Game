## 玩家看到的变化

### 2026-10-15：像素风技能树界面

按用户“改ui”的要求，技能页改为带像素场景背景和立体边框的界面。顶部集中显示角色等级、可用技能点和分支进度；三个技能使用像素书卷图标和路线连接，可解锁、未满足条件、已解锁及当前等级分别显示状态。可操作的金色按钮有按下反馈。

每张卡片仍直接显示具体条件，通用规则收进可展开说明。说明支持键盘 Enter／空格操作，切换语言保留展开状态。提示和重试入口放在技能路线前方；手机纵屏改为纵向路线，短横屏确认框保留费用、剩余点数、效果和按钮。

技能页缓存版本为 `20261015-skillui1`。只调整界面和三个中英文标签，技能规则、扣点与战斗效果保持不变；无需导入 SQL。实际接口浏览器测试通过 EN/ZH 七种屏幕尺寸、按钮按下反馈、说明键盘操作、三段解锁、异常重试及返回地图；规定的游戏客户端验证地图移动。截图已检查，正式玩家数据库未参与测试。

### 2026-10-15：补清楚提示与解锁限制

三个等级的花费、角色等级门槛及伤害数值保持原样。每张未解锁卡片现在同时列出前置技能、当前／要求等级、当前技能点／本级花费，并明确显示还差几级、还缺几点。每一级分别扣点，已解锁等级不会重复购买；当前总加成、被更高等级替代的效果和分支满级都有明确提示。

确认弹窗显示“现有点数 → 本次花费 → 剩余点数”和“旧加成 → 新加成”，再次说明加成不累加、从下一场战斗生效。取消／Escape 不扣点并返回原按钮焦点。未满足条件、加载失败或另一个解锁尚未确认时，确认按钮不可用，卡片也显示相应原因。

服务器仍在事务中重新检查条件。若确认前等级或点数发生变化，页面显示准确的拒绝原因并重新读取条件；若解锁已提交但回包丢失，只能确认同一目标，不会自动买下一级。登录或 CSRF 过期时提供刷新页面入口，避免反复重试旧凭证。读取失败会清空旧的可解锁状态，读取恢复前不会允许依据旧余额购买。

相关文件为 `skills.php`、`js/skills.js`、`css/skills.css`、`js/i18n.js` 和 `tests/skills.test.cjs`。技能页独立更新缓存版本 `20261015-skillhints1`；保留工作区已有的任务指引与共用模块修改，不替换其内容。没有新增图片或 SQL 更新。

## 保存和权限

没有新增 SQL migration，也没有新增图片。使用现有 `players.skill_points_total` 和 `player_skill_point_transactions` 保存购买；固定描述 `EPQ:word-strike:1..3` 与 `SKILL_PURCHASE` 类型记录此分支的永久解锁。旧原型的 `skills` / `player_skills` 表未接入本轮运行流程。

购买由登录会话确定玩家，检查 CSRF、前置等级、角色等级与服务器技能点余额。事务先锁定玩家，扣点和写入解锁记录一起提交，失败一起回滚。每次请求指定目标等级，重复提交同一目标只确认已完成解锁；丢失返回信息后重试不会购买下一级。客户端传入的 player_id、花费、加伤数值没有权限。

新战斗从服务器解锁记录读取技能等级，保存到原有 verified_battles.state_json；已有战斗缺少该字段时按未解锁处理。答对才应用加伤，语法/句子/IT English 题不额外加伤，技能不会增加学习正确率或伪造奖励。

没有访问或重置用户的实际 3306 数据库。数据库与浏览器测试使用临时 3307 数据库、8081 PHP 服务和测试玩家。

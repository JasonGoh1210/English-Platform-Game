# 登录和注册输入提示

注册用户名为3–30位英文字母、数字、点、横线或下划线；提交时统一去掉首尾空格并转成小写。用户名不可重复，大小写不同也视为同名。这里指登录用的用户名，角色名字继续在创建角色页面设置。

新注册和游客设置永久密码时，密码至少8个字符，必须有至少1个大写英文字母 A–Z 和至少1个数字0–9。小写字母与符号可使用，但不强制要求；密码不去空格、不改大小写。确认密码必须完全一致。为避免当前 bcrypt 的72字节截断，新密码最多72字节；页面对过长的输入给出提示，中文按实际字符数检查最低长度，同时遵守字节上限。

登录页面提示输入原用户名与原密码，不把新的注册强度要求施加给旧账号。显示／隐藏密码、大写锁定提示与自动填充继续可用。Google 账号密码由 Google 页面处理，这些表单规则不改变 Google 授权。

注册输入用户名后400毫秒检查可用性，具有六秒超时与过期响应保护。接口要求同一会话的 CSRF，不返回用户ID／邮箱，只返回当前名字是否可用。检查断网时仍可提交，注册服务器和数据库唯一索引进行最终判定。密码与确认密码不会发送给可用性接口。游客升级也显示准确的重名／邮箱冲突错误；失败不改变当前游客，成功保留相同 user_id／player_id、地图、金币与背包。

前端脚本 `js/auth-form.js` 给出字段错误和密码逐项提示；关闭或绕过 JavaScript 后，`includes/account_rules.php` 与 `register.php` 仍会拒绝不合规则的提交。错误提交不回填密码。控件通过 aria-describedby、aria-invalid 和状态区连接提示，窄屏输入框可以收缩，避免被面板裁切。

验证：`tests/account_rules_test.php` 检查边界、Unicode长度、密码上限与表单类型；`tests/account_flow_smoke.php` 在独立数据库通过真实 HTTP 验证弱密码拒绝、用户名格式／大小写重名、邮箱冲突、CSRF、无效提交不新增账号、游客升级保存及旧弱密码登录。GitHub 的两种数据库任务均包含该测试。本机 Chrome 另外检查实际输入交互、过期可用性回包、断网回退、Google 按钮共存与320／390像素窄屏。

没有数据库结构或素材更新，无需重新导入SQL；本次没有修改正式玩家数据。更新后按 Ctrl+F5 刷新 `/FYP/login.php` 和 `/FYP/register.php`。

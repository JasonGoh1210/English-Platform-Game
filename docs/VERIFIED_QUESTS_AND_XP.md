# 服务器任务奖励与经验条

## 这次完成

- NPC 奖励的金额和剧情顺序由 PHP 固定，浏览器只提交 NPC ID 和领取凭证。四个 NPC 的位置、奖励和剧情保留。
- 每个 NPC 对每个角色只发一次章节奖励。重复请求或换一个请求编号都不能重复领。
- 打字挑战由服务器发出单词和题目凭证，并判定答案。三关仍各奖励 10 XP、5 金币、1 英语力量；答错不奖励。重玩依然可以通过正确作答获得练习奖励。
- 第三关通过时，服务器在同一事务内确认结局和一次性的 50 XP、25 金币、2 英语力量奖励。未完成三关不能靠上传 `questStep=5` 领取结局。
- 旧 `api/save_progress.php` 已关闭客户端金额入口。旧缓存客户端会收到要求刷新页面的错误。
- 不确定的任务请求按玩家保存到浏览器，再用同一个编号重放。升级账号／重新登录后使用当前 CSRF；不会重复发奖。失败时不先增加本地金币或 XP。
- 经验条使用 MySQL `levels` 门槛。例如 2 级、总 XP 246 显示本级 `146 / 150`、97.33%；升级后重置为新级进度，满级显示“满级／MAX”。总 XP 仍原样保存。

## 现有 XAMPP 的更新

1. 在 phpMyAdmin 导出 `english_power_quest` 备份，并确认之前 002–006 更新已完成。
2. 选择该数据库，导入 **`database/migrations/007_verified_quests.sql`**。
3. 007 只新增任务进度、领取凭证、打字挑战和请求凭证四个表。首次导入从旧地图存档和旧章节奖励账本接续已完成章节；不重发旧奖励、不改原名字、XP、金币或世界位置。
4. 重复导入不重置新的已验证进度。不要导入完整 schema 或 demo seed 覆盖现有数据库。
5. 更新代码后按 Ctrl+F5，再进入游戏。`git pull` 只更新文件，不执行 SQL。

本次没有对你的实际 XAMPP 玩家数据库执行迁移。只有全新空数据库才使用完整 `database/english_power_quest_schema.sql`。

## 保存与重试

请求和奖励／账本／章节变更在同一事务完成。账本失败会回滚领取凭证与余额；恢复连接后仍可用同一请求编号重试。已提交但响应丢失时，服务器返回原结果及当前余额，避免重复增加或恢复过时余额。

旧角色保留当前位置、剧情、教程状态、角色外观和账号。游客升级仍保持相同 player_id，所有新凭证也跟随这个角色。打字挑战本身继续采用重新进入／重玩重新开始三关的行为；已确认奖励与章节保存到 MySQL。

## 边界

服务器验证章节顺序、保存的位置范围、题目凭证和拼写，固定奖励并防重复。地图移动、打字怪物步进和计时仍在 Canvas 客户端运行；保存的位置也是客户端报告的。单词拼写仍用于既有提示和反馈，所以这次没有实现防脚本／防查看题库机制。网络等待期间暂停本地打字挑战，不因请求慢而增加怪物步数。

这次没有新增素材，也没有改变战斗的答题、伤害、药草或奖励规则。

## 主要文件与检查

- `includes/quests.php`、`api/quests.php`：固定奖励、章节、打字判分和领取事务。
- `js/quest-api.js`、`js/rpg.js`：保存请求、恢复重放、确认后更新界面。
- `includes/progression.php`、`includes/rewards.php`、`api/player.php`、`index.php`：经验门槛与显示。
- `api/game_state.php`：章节由已验证记录决定；继续保存其他地图和教程数据。
- `api/save_progress.php`：阻止旧客户端自定奖励。
- `database/migrations/007_verified_quests.sql`：增量迁移；完整 schema 仅用于空数据库。
- `tests/quests_flow_smoke.php`、`tests/quest_api.test.cjs`、`tests/progression_test.php`：所有权、CSRF、剧情顺序、重放／冲突、三关、结局、练习、旧存档、回滚及经验边界。

详细浏览器与 GitHub 测试结果记录于 `progress.md`。
